## 1. Модель нормализованного события

Схема полей событий — набор полей и их допустимых значений для сохранения информации о событиях на всех этапах обработки. Нормализованное событие представляет собой совокупность полей, заполненных данными из необработанного события согласно правилу нормализации.

Внутренний стандарт записи событий MP SIEM разработан на основе **Common Event Expression (CEE)**.

В JSON-представлении результата нормализации используются плоские ключи; точка является частью имени поля:

```json
{
  "event_src.vendor": "cisco",
  "event_src.title": "asa",
  "src.ip": "192.0.2.10",
  "subject.account.name": "alice"
}
```

### Основные смысловые группы

| Группа | Смысл |
|---|---|
| `event_src.*` | Приложение или узел, который зарегистрировал событие |
| `src.*`, `dst.*` | Источник и получатель описываемого взаимодействия |
| `subject`, `subject.*` | Субъект, который выполняет действие |
| `action` | Характер действия |
| `object`, `object.*` | Объект, над которым выполняется действие |
| `status` | Результат действия |
| `importance` | Важность события для информационной безопасности |
| `category.generic/high/low` | Иерархическая категоризация события |
| `recv_*` | Точка, от которой MP SIEM получил событие |
| `body` | Исходный текст необработанного события |

`event_src.*` не следует смешивать с `src.*`: например, межсетевой экран, зарегистрировавший запись, является `event_src`, а узлы участвующего в записи сетевого соединения — `src` и `dst`.

## 2. Обязательность

Столбец «Обязательное» официальной схемы указывает необходимость заполнить поле **в правиле нормализации или корреляции**.

Обозначения в таблицах ниже:

- **Да** — обязательно;
- **Нет** — необязательно;
- **Нормализация** — обязательно при нормализации;
- **Корреляция** — обязательно при корреляции;
- **Авто** — заполняется автоматически;
- **Нормализация / авто при корреляции** — обязательно при нормализации и заполняется автоматически при корреляции.

Обязательные поля правила нормализации:

| Поле | Тип | Назначение |
|---|---|---|
| `time` | `DateTime` | Время события в MP SIEM, UTC+0 |
| `event_src.title` | `String` | Название приложения-источника |
| `event_src.vendor` | `String` | Производитель приложения-источника |
| `event_src.category` | `Enum` | Категория источника события |
| `action` | `Enum` | Характер воздействия на объект |
| `object` | `Enum` | Объект воздействия |
| `status` | `Enum` | Конечный результат воздействия |
| `importance` | `Enum` | Важность события для ИБ |
| `id` | `String` | Идентификатор в заданном формате правила нормализации/корреляции |

`subject` и поля `category.generic`, `category.high`, `category.low` не являются обязательными по схеме 8.0.

## 3. Типы данных

| Тип | Описание | Пример |
|---|---|---|
| `Bool` | Логическое значение | `true`, `false` |
| `Buffer` | Массив байтов | `[0x68, 0x65, 0x6c, 0x6c, 0x6f]` |
| `DateTime` | Время ISO 8601 | `2016-04-20T23:04:38Z` |
| `Enum` | Один элемент предопределённого списка значений | — |
| `IPAddress` | IPv4 или IPv6 | `192.0.2.235`, `1080:0:0:0:8:800:200C:417A` |
| `KeyValue` | Ассоциативный массив пар «ключ — значение» | `{"key":"value"}` |
| `List` | Список, который может содержать элементы разных типов | `["Порт ", 22, " открыт"]` |
| `MACAddress` | MAC-адрес | `00:53:00:B8:DF:B8` |
| `Network` | Подсеть IPv4/IPv6 с маской CIDR | `192.0.2.0/24` |
| `Null` | Отсутствие данных | `null` |
| `Number` | Целое signed 64-bit число | `-3`, `0`, `12` |
| `String` | Строка | `"Порт 22 открыт"` |
| `StringList` | Список строк | `["one", "two"]` |
| `UUID` | 128-битный идентификатор RFC 4122 | `123e4567-e89b-12d3-a456-426655440000` |
| `UUIDList` | Список UUID | `["00000005-9d7c-011d-f000-0001e5c6e294"]` |

Для `DateTime` в схеме событий используется UTC+0. `Number` — целое число, не число с плавающей точкой.
