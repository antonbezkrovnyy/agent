## Краткий результат

**Модель сохранила конверт и payload, вернула RAW, правильно отнесла `severity/action/protocol` к `dynamic`, а порты и hit-маркер сделала опциональными. Но `raw` снова назван `static`, а `msg_id` оставлен необязательным несмотря на использование как ключа диспетчеризации.**

## Что исправлено относительно R008

| Проблема R008 | Результат R009 |

## Итоговая схема

| Группа | Поля |
|---|---|
| RAW | `raw` |
| Конверт | `pri`, `timestamp`, `host`, `msg_tag`, `msg_id`, `severity` |
| Событие | `acl_name`, `action`, `protocol` |
| Source | `src_iface`, `src_ip`, `src_port` |
| Destination | `dst_iface`, `dst_ip`, `dst_port` |
| Агрегация | `hit_cnt`, `hit_flag` |
| Непрозрачный хвост | `hex_ids` |

Такой состав уже может служить спецификацией для последующего детерминированного разбора: статические элементы задают грамматику, динамические — captures, а `required` — опциональные группы.

## Оставшиеся ошибки

### 1. `raw` снова `static`

```json
{
  "name": "raw",
  "category": "static",
  "required": true,
  "source": "$"
}
```

RAW меняется на каждом наблюдении и должен быть `dynamic`. Правило, которое исправило `severity`, не было обобщено моделью на исходную строку.

### 2. `msg_id` необязателен

```json
{
  "name": "msg_id",
  "category": "static",
  "required": false,
  "source": "$.tag.msg_id"
}
```

Одновременно стратегия использует `msg_id` как ключ диспетчеризации. Для данной Family ключ должен быть обязательным, иначе невозможно выбрать её грамматику тела. Generic fallback для отсутствующего идентификатора относится уже к другому пути разбора и не отменяет контракт текущей Family.

## Вывод

**R009 — ближайший к рабочей спецификации результат.** Для следующего шага достаточно точечных правил:

- `raw` всегда `dynamic` и `required=true`;
- ключ диспетчеризации `msg_id` для текущей Family `static` и `required=true`.
