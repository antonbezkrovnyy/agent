# R018 — полный Cisco corpus с пустого Registry

> Все 1763 непустые строки `artifact_cisco_firewall.log` обработаны с пустой БД и без встроенных Grok. Только 9 строк потребовали ReAct-исследования; остальные 1754 были покрыты сохранёнными parser revisions без вызова модели. Итоговая проверка подтвердила отсутствие непокрытых строк и ошибок.

## Методика

Перед каждой строкой runner детерминированно исполняет **все сохранённые parser revisions**:

```text
RAW
→ execute всех сохранённых revisions
→ проверка required fields, типов и residual
→ если совпадение есть: COVERED, LLM не вызывается
→ если совпадения нет: UNCOVERED → новый независимый ReAct-диалог
→ semantic search + fallback
→ создание или расширение parser
→ evaluate_candidate
→ сохранение Grok и Family
→ независимая проверка Response runner-ом
→ сохранение research result
```

Модель и HTTP-клиент переиспользуются, но история диалога между непокрытыми строками не передаётся. Общее состояние находится только в SQLite.

Для консоли RAW сокращается до 180 символов; в ReAct и JSONL передаётся полная строка.

После обработки выполнен второй полный проход по всем 1763 строкам со всеми сохранёнными revisions.

Semantic search использовался для получения кандидатов, но покрытие определялось только полным совпадением parser и валидацией результата.

## Прогресс и устойчивость к перезапуску

Прогресс выводился построчно в реальном времени и одновременно записывался в JSONL.

После перезагрузки ноутбука фоновый процесс прервался на строке 104. Состояние на диске содержало:

- 103 завершённых события;
- 4 research results;
- 4 parser revisions;
- 32 Grok.

Обработка была перезапущена **без `--reset`**. Строки 1–103 повторно подтверждены сохранёнными parser без LLM, строка 104 исследована заново. Повторные research results для ранее завершённых строк не создавались. Итоговая сводка учитывает оба запуска; `duration_seconds` относится к повторному запуску, а не ко всему wall-clock эксперимента.

## DuckDuckGo

Отдельная проверка показала нестабильность поиска:

- `Cisco ASA 106023` — `No results found`;
- `Cisco ASA syslog 106100` — `No results found`;
- `RFC 5424 syslog` — timeout при обращении к Yahoo.

Это не остановило corpus: документация является дополнительным доказательством, а не обязательным условием. Ошибки поиска возвращались как `search_failed`, ReAct продолжал анализ RAW. Семантика полей, требующая внешней документации, не считается подтверждённой этим экспериментом.

## Ограничения

- Проверено структурное покрытие corpus, а не эталонная правильность каждого поля.
- Corpus содержит только 3 обнаруженные Family; универсальность для новых источников не доказана.
- Некоторые строки совпадают с несколькими revisions. Текущий runner фиксирует все matches и выбирает первую для журнала, но production-приоритет ревизий не определён.
- Жизненный цикл `candidate → validated → published` отсутствует.
- Независимая внешняя документация из-за DuckDuckGo получена не для всех неоднозначных полей.
- Нет отдельного golden-набора для оценки семантической точности и полноты `record_schema`.

## Вывод

**R018 — текущий системный baseline.** Система начала с пустого Registry и нуля встроенных Grok, обнаружила 9 различимых грамматических случая и использовала их для покрытия всего corpus. Доля строк, потребовавших модельного исследования, составила около **0,51%**; остальные были обработаны детерминированно.

Перезапуск подтвердил, что SQLite и JSONL позволяют продолжить длительный эксперимент без потери накопленного состояния.
