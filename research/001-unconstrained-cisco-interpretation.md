### Что это за строка

Это syslog-сообщение от межсетевого экрана **Cisco ASA**. Формат строки: `PRI → дата/время → адрес источника лога → Message ID → параметры события`.

### Разбор по полям

| Поле | Значение | Расшифровка |
|---|---|---|
| `<132>` | PRI | 132 = facility 16 (`local0`) × 8 + severity 4 (`warning`) |
| `Feb 12 2023 13:00:30` | время | 12 февраля 2023, 13:00:30 (часовой пояс — по настройке устройства) |
| `10.11.200.67` | источник | IP самой ASA, отправившей сообщение в syslog |
| `%ASA-4-106100` | Message ID | ASA, severity 4 (warning), сообщение **106100** — логирование попадания в ACE списка доступа |
| `access-list CSM_FW_ACL_` | имя ACL | какой список доступа сработал; префикс `CSM_` — типичная подпись ACL, сгенерированного Cisco Security Manager (обратите внимание: завершающий `_` — часть имени, оно не обрезано) |
| `denied tcp` | действие/протокол | соединение **запрещено**, протокол TCP |
| `Outside/131.9.85.43(14015)` | источник пакета | интерфейс `Outside`, IP 131.9.85.43, порт 14015 |
| `-> PUB_DMZ/191.189.210.52(22)` | назначение | интерфейс `PUB_DMZ`, IP 191.189.210.52, порт **22 (SSH)** |
| `hit-cnt 1 first hit` | счётчик | это **первое** совпадение с данным правилом; следующее сообщение по тому же потоку придёт уже с накопленным счётчиком (за интервал логирования) |
| `[0x6921d058, 0x00000000]` | хэши | внутренние идентификаторы ASA для корреляции повторных сообщений по этому же потоку (полезны при обращении в TAC); второе поле обычно нулевое |

### Суть события

Пакет из внешней сети — с публичного адреса **131.9.85.43** (исходный порт 14015, эфемерный) — пытался установить TCP-соединение с **портом 22 (SSH)** хоста **191.189.210.52** в сегменте `PUB_DMZ`. На ASA для этого трафика не нашлось разрешающего правила, и он был **отброшен** (deny в `CSM_FW_ACL_`, в типовой схеме это встроенный deny при переходе с более низкого уровня безопасности `Outside` на более высокий `PUB_DMZ`). Соединение не создавалось, до сервера пакет не дошёл, ответа не было.

Сработал сам механизм фильтрации, то есть ASA выполнил свою функцию корректно — это не сбой, а штатное логирование блокировки.

### На что обратить внимание

1. **Признак сканирования/брутфорса.** Эфемерный исходный порт + попытка стучаться в 22/tcp снаружи — характерная картина автоматического сканера или перебора SSH, а не живого админа. `first hit` означает, что поток новый; появление серии таких же строк с этим IP и растущим `hit-cnt` — уже явный признак целенаправленного перебора.
2. **Проверить, нужен ли SSH из интернета.** Если доступ к 191.189.210.52 нужен — правило должно быть узким (конкретные разрешённые source-IP, VPN/джамп-хост, ограничение по времени), а не `any`. Если не нужен — убедиться, что блокировка ожидаема и сервер не уязвим по другим каналам.
3. **Шум в логах.** Сообщения 106100 при большом объёме трафика могут забивать syslog-сервер и диск самого ASA. Стоит проверить настройки `logging`, rate-limiting и интервального логирования; при массовых одинаковых записях имеет смысл отдать их на корреляцию в IDS/SIEM.
4. **Проверить историю по IP 131.9.85.43** — были ли ещё попытки на другие порты/хосты, и при необходимости занести в блок-лист (или добавить временный deny).
5. **Помнить про CSM.** ACL `CSM_FW_ACL_` управляется из Cisco Security Manager: ручные правки на ASA при следующем деплое будут перезаписаны, изменение нужно вносить через CSM.
